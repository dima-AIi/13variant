# Протокол самостоятельной инспекции кода

Объект — версия 0.9.0 собственной мебельной мастерской. Партнёрская рецензия не проводилась. Проверены основные пути входа, выбора заказа, файлового обмена, расчёта статистики и выпуска.

| № | Область | Уровень | Наблюдение и результат |
|---|---|---|---|
| 1 | WorkshopHost | Важный | Встроенный API использовал HTTP. Добавлено HTTPS на loopback. |
| 2 | App | Важный | Сертификат локального сервера нужно отличать от любого системного сертификата. Клиент проверяет SHA-256 своего сертификата и имя хоста. |
| 3 | WorkshopEndpoints | Важный | CanConnect подтверждал только вход в SQLite. Health проверяет таблицу заказов и отвечает 503 при ошибке. |
| 4 | WorkshopHost | Важный | 30 попыток входа в минуту превышали учебный лимит. Установлено пять, покрыто тестом HTTP 429. |
| 5 | WorkshopDialogs | Важный | 1,500 превращалось в 1,50. Неоднозначный ввод отклоняется. |
| 6 | WorkshopDialogs | Важный | Разбор даты зависел от DatePicker и состояния события валидации. Разбор переведён на два явных формата. |
| 7 | WorkshopFiles | Средний | Пустая первая строка мешала выбрать разделитель. Заголовок читается после пропуска пустых строк. |
| 8 | OrderRules | Средний | Дата завершения раньше создания искажала среднее. Отрицательная длительность исключена. |
| 9 | OrdersController | Средний | Статистика читала полную карточку с JOIN. Используется проекция четырёх полей. |
| 10 | OrderRules | Средний | Список заказов обходился несколько раз. Статистика теперь собирается за один проход. |
| 11 | ApiTests | Средний | Тесты требовали учебные пароли для CI. Тестовая база получает случайный пароль только на время прогона. |
| 12 | WorkshopClient | Низкий | Задержка и отказ соединения давали одинаковое сообщение. Для тайм-аута добавлено отдельное пояснение. |

Инспекция проводилась по исходным файлам, затем исправления подтверждались тестами, запросами на живой API и сравнением замеров.
