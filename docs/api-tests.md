# Проверка API и прав

Откройте `requests.http` в Visual Studio. Для проверки используйте отдельную чистую SQLite с учебными данными. Файл запросов создаёт и меняет записи. Задайте четыре переменные паролей из README в окружении, из которого запущена Visual Studio. Для этой матрицы используются admin, manager и ivan. В PowerShell из папки решения:

```powershell
$env:Workshop__Database = Join-Path ([IO.Path]::GetTempPath()) ("workshop-http-" + [Guid]::NewGuid() + ".db")
$env:Workshop__SeedDemo = 'true'
dotnet run --project FurnitureWorkshop.Api --launch-profile Local
```

Выполняйте запросы по порядку. Именованные ответы входа и подготовки заказов используются дальше для подстановки JWT и номера заказа. Swagger UI находится по адресу `http://127.0.0.1:5130/swagger`. В Swagger сначала выполните вход, затем вставьте полученный JWT в окно Authorize.

## Ошибки

| Сценарий | HTTP | Что получает клиент |
|---|---:|---|
| Ошибка JSON, фильтра или обязательного поля | 400 | `ProblemDetails` или `ValidationProblemDetails` |
| Заказ нарушает правило перехода | 400 | Сообщение о требуемых данных |
| CSV содержит ошибки | 400 | Причина и массив `errors` с полями `line` и `message` |
| Неверный пароль, пустой/отозванный токен | 401 | Запрос входа или сообщение о завершении сеанса |
| Недостаточная роль | 403 | Сообщение о запрете действия |
| Заказ отсутствует или назначен другому сборщику | 404 | Сообщение о недоступности заказа |
| Устаревшая версия заказа | 409 | Обновить список и повторить действие |
| CSV превышает 1 МиБ | 413 | Сообщение о размере файла |
| Лимит попыток входа | 429 | Сообщение о повторе через минуту |
| Внутренний сбой | 500 | Общий ответ, подробности в журнале API |
| SQLite недоступна для проверки /health | 503 | Сообщение о недоступности базы |

Проверка дефекта входа `UnreadableStoredHashRejectsLoginWithoutServerError` подставляет повреждённый хеш в временной SQLite и ожидает 401. Номер версии заказа защищает от повторной записи по устаревшей карточке. Явная проверка версии находится в модели приложения, EF Core дополнительно проверяет токен конкурентности в SQL при сохранении.
